## Global Constraints

- Todas las rutas CRM van bajo `/api/v1/...` y son ruteadas por el gateway (`Src/Gateway/CreditApiGateway/appsettings.json`) hacia `crm-backend` cuando el path matchea `applications`, `credit-applications`, `customers`, `documents`, `external-customers`, `prospects`, `risk-evaluations`, `risk-matrices`, `risk-rules`, `workflows`. Todo lo demás va a `credit-backend` (Core). Esto confirma que **un solo `IApiClient`/`BaseUrl` sirve para ambos** — ya no es un supuesto, es un hecho verificado.
- El backend CRM (`Crm.WebApi`) **no exige API Key** en local (confirmado con `curl` sin headers, 200 OK). No agregar lógica de auth nueva; seguir usando el mismo `ApiKeyAuthorizationHandler` ya configurado (no-op si `ApiSettings.ApiKey` está vacío).
- Ningún endpoint CRM soporta `PATCH` salvo `PATCH /api/v1/customers/{customerId}/financials` — y `IApiClient` hoy no tiene `PatchAsync`. Se agrega en la Fase 4 (Customers), replicando exactamente el patrón de `PutAsync<TRequest>`/`DeleteAsync`.
- Todos los DTOs del swagger CRM tienen `"additionalProperties": false` y prácticamente todos los campos `string` son `nullable: true` sin `enum` — replicar como `string?` salvo que ya exista un enum C# análogo en el repo (no crear enums nuevos sin pedirlo explícitamente; los enums inferidos `RiskRuleType`/`RiskMatrixStatus`/`RiskRuleTargetField` se eliminan en la Task 0.2; `Status` de matriz se expone como constantes en `RiskMatrixStatuses`).
- Convención de nombres de archivo/response: sufijo `Response` para DTOs de salida, `Request` para entrada (el repo no usa el sufijo `Dto` del backend). Namespace `CreditSystem.Frontend.Web.Models.{Requests,Responses,Common}`.
- Cabecera obligatoria en cada archivo generado 1:1 desde swagger: comentario `// <auto-generated>` apuntando al swagger CRM, igual que los archivos `RiskEngine` ya existentes.
- Verificación de cada fase: `dotnet build` limpio + smoke test manual con `DummyData:Enabled=false` y `Api:BaseUrl=http://localhost:5000/` contra el backend real corriendo localmente.

**Reglas de dominio que el frontend debe respetar** (no modelar lo que no existe):

- **No existe `PUT /risk-matrices/{id}`** (405). "Editar" una matriz = `new-version`, que crea un `Draft` con `version = origen + 1` y `id` distinto. El origen pasa a `Superseded` solo cuando ese Draft se activa.
- Estados: `Draft` → `Active` → `Superseded`. Solo un `Draft` se puede activar o borrar.
- `PUT` de regla: bloqueado si está en una matriz `Active` o `Superseded`. `DELETE` de regla: bloqueado si está en **cualquier** matriz (incluso `Draft`). Para cambiar una regla en uso: crear regla nueva + nueva versión de matriz.
- `ruleType` ∈ `RangeCheck` | `ThresholdCheck` | `EnumCheck`. `targetField` sin catálogo confirmado. `parameters` es `Record<string,string>`.

**Decisión de tipos:** `RuleType`, `TargetField` y `Status` se modelan como `string` (regla del plan: no inventar enums no confirmados). Solo el catálogo de `Status` está confirmado, por lo que se expone en un helper de constantes. Los enums `RiskRuleType`, `RiskRuleTargetField` y `RiskMatrixStatus` existentes se **eliminan** (sus valores eran inferidos y erróneos: `Archived` debía ser `Superseded`; `MinThreshold`/`Range`/`Blacklist`/… no existen).

public async Task<ApiResult> PatchAsync<TRequest>(string requestUri, TRequest body, CancellationToken ct = default)
{
    var client = _httpClientFactory.CreateClient(ApiClientConstants.HttpClientName);

    try
    {
        using var request = new HttpRequestMessage(HttpMethod.Patch, requestUri)
        {
            Content = JsonContent.Create(body, options: SerializerOptions)
        };

        using var response = await client.SendAsync(request, ct);
        return await ReadResponseAsync(response, ct);
    }
    catch (Exception ex) when (ex is HttpRequestException or TaskCanceledException)
    {
        return ApiResult.Failure(BuildTransportError(ex, requestUri));
    }
}
