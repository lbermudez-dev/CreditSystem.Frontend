# Frontend — Sistema de Gestión de Crédito (CACE)

Blazor Web App (.NET 9, render mode **Interactive Server**) que consume la
API REST descrita en `open_api.json` (OpenAPI 3.0.1, "Credit System API",
54 endpoints bajo `/api/v1/`). El diseño visual replica los HTML de
referencia (`Dash.html`, `ExpedientePersona.html`, `Creditos.html`) usando
**Bootstrap 5** (vía LibMan, no CDN) + un set de tokens CSS propios.

---

## 1. Requisitos

- .NET 9 SDK
- Bootstrap **no viene incluido** en este zip (ver sección 2)

> Este proyecto fue generado en un entorno sin acceso a internet ni al SDK
> de .NET, por lo que **no se pudo ejecutar `dotnet build` ni descargar
> Bootstrap**. Es necesario compilar y restaurar por primera vez en tu
> máquina antes de dar esto por validado.

## 3. Configuración de la API (BaseUrl / ApiKey)

```json
"Api": {
  "BaseUrl": "https://REEMPLAZAR-CON-BASE-URL-REAL/",
  "ApiKey": "",
  "ApiKeyHeaderName": "X-Api-Key"
}
```

- **BaseUrl**: cada servicio ya arma sus rutas con el prefijo `api/v1/...`
  (confirmado en `open_api.json`), así que `BaseUrl` debe ser solo el host.
- **ApiKey**: usar User Secrets en desarrollo (`dotnet user-secrets set
  "Api:ApiKey" "..."`), nunca dejarla en `appsettings.json`.
- **ApiKeyHeaderName**: el swagger real **no define ningún `securityScheme`**
  — sigue sin confirmarse el mecanismo exacto de autenticación. Se asume
  `X-Api-Key` como placeholder; ajustar en configuración cuando se confirme
  (no requiere tocar código, ver `ApiKeyAuthorizationHandler.cs`).

## 4. Origen de los modelos (`Models/`)

Todos los archivos bajo `Models/Requests`, `Models/Responses` y
`Models/Enums` fueron **generados automáticamente a partir de
`open_api.json`** (73 schemas) — no son suposiciones. Cada archivo lleva un
encabezado `// <auto-generated>`. Si el swagger cambia, la forma correcta de
actualizar es volver a generarlos contra el nuevo spec, no editarlos a mano
uno por uno.

Dos particularidades del spec real que vale la pena tener presentes:

- **Los enums viajan como enteros**, no como strings (`AmortizationMethod`,
  `GuaranteeStatus`, `GuaranteeType`, `PaymentComponent`, `ProductStatus`,
  `SocialCapitalCalculationType`, `SocialCapitalCollectionMode`). El swagger
  no expone `x-enumNames`, así que los **nombres** de cada valor (ej.
  `French = 0`) son una inferencia razonable y están marcados
  `DOCUMENTACION INSUFICIENTE` en el propio archivo — el **valor entero sí
  es el contrato real** y no debe tocarse.
- **Los campos `status` de `LoanSummaryResponse` y
  `RevolvingCreditSummaryResponse` son `string` libres**, no enums. Los
  literales que reconoce `StatusBadge.razor` (`Active`, `Delinquent`,
  `Default`, etc.) son igualmente una inferencia — confirmar contra el
  backend real.
- **No todos los responses traen `currency`** (ej. `LoanSummaryResponse`,
  `DelinquentLoanResponse`). Se usa `CurrencyFormatter.DefaultCurrency`
  ("NIO" — córdoba nicaragüense, símbolo `C$`) como *fallback* de solo
  presentación cuando el campo no viene en la respuesta.

## 7. Documentación insuficiente (consolidado)

1. **Autenticación**: el swagger no define `securityScheme`. Se asume
   ApiKey vía header configurable (`X-Api-Key` por defecto).
2. **Nombres de valores enum**: ver sección 4 — el entero es el contrato
   real, los nombres son inferencia.
3. **Literales de `status` (string)**: ver sección 4 y `StatusBadge.razor`.
4. **Moneda por defecto**: varios responses no traen `currency` — ver
   `CurrencyFormatter.DefaultCurrency` ("NIO").
5. **Formato de `amortization-table`**: el query param `format` es
   `string` libre, sin catálogo de valores documentado (se usa `"pdf"` por
   defecto en el botón de descarga).
6. **Descarga real de archivos en el navegador**: `IDocumentService` ya
   trae los bytes correctamente tipados (`DocumentFile`), pero falta el
   interop JS (`URL.createObjectURL` + click en un `<a>`) para disparar la
   descarga automática — es una adición menor y aislada.
7. **KPIs agregados de dashboard** (cartera total, socios activos): siguen
   sin existir en el swagger.

## 8. Cómo continuar

1. Restaurar Bootstrap (sección 2) y confirmar que compila.
2. Confirmar BaseUrl y esquema de autenticación real.
3. Agregar el interop JS de descarga de archivos (punto 6).
4. Definir y construir las pantallas de Async Payments, Reference Rates y
   Webhooks si el negocio las necesita.
5. Confirmar los nombres reales de los enums y los literales de `status`
   contra el código fuente del backend, y actualizar los comentarios
   `DOCUMENTACION INSUFICIENTE` correspondientes.
